# AGENTS.md

Personal Arch Linux / Hyprland dotfiles. The repo is the source of truth; `install.sh` symlinks its directories into `~/.config`, so edits are effectively live desktop changes. There is no build, test suite, linter, or CI.

## Setup and deployment
- `git submodule update --init --recursive` — `kitty/`, `nvim/`, `tmux/`, `zshrc/` are separate `MoLiYue/*` repos. Commit changes inside them there, then bump the gitlink in this repo.
- `./install.sh` is idempotent: links `hypr`, `waybar`, `rofi`, `swaync`, `matugen`, `mpd`, `rmpc`, `themes`, `scripts`, `kitty`, `fastfetch`, `yazi`, `nvim` and individual files, seeds `~/.config/theme-current` + `current-theme`, then runs `scripts/theme-adapters.sh`.
- Verification: `bash -n <script>` for shell changes; after Hyprland changes run `hyprctl reload` and check `hyprctl configerrors`.

## Entry points
- `hypr/hyprland.lua` is the real Hyprland entry (0.56+ Lua config); it loads `hypr/conf/` modules via `require("conf/...")`.
- `hypr/hyprland.conf` is an autogenerated stub (`autogenerated = 1`), not the live config.
- `hypr/conf/cursor.conf`, `layouts/layout.conf`, `windows/window.conf`, and `keybindings/default_bak.conf` are legacy Hyprlang and are **not loaded** by the Lua entry.
- Session flow: `conf/autostart.lua` → `scripts/desktop-ui.sh`, which restores the saved theme and starts SwayNC + Waybar.
- Theme CLI: `scripts/apply-theme.sh <name>|--restore|--wallpaper <img>`, `scripts/wallpaper.sh`, `scripts/theme-adapters.sh`.

## Theme system (biggest gotcha)
- One active source: `~/.config/theme-current` → `themes/<name>/apps/` (preset) or `~/.cache/mlyue-theme/wallpaper/` (Matugen output).
- An activated theme directory must contain all five non-empty files: `waybar.css`, `rofi.rasi`, `kitty.conf`, `swaync.css`, `hyprland.lua`. Activation fails otherwise.
- `theme-adapters.sh` creates absolute-target symlinks `waybar/colors.css`, `rofi/colors.rasi`, `swaync/colors.css`. They are gitignored runtime files — never commit them.
- Waybar/Rofi/SwayNC only include those same-directory adapters. Do not use `../theme-current` in app configs: the config dirs are symlinks, so `..` resolves inside this repo. Hyprland reads the absolute `config_home .. "/theme-current/hyprland.lua"` path.
- `~/.config/current-theme` stores either a preset name or `wallpaper`; it is what login restore reads.
- Adding a preset: create `themes/<name>/colors.sh` with the `BG`/`FG`/`ACCENT`/`HYPR_*` variables consumed by `apply-theme.sh`, plus an optional `apps/` dir. Without `apps/`, `apply-theme.sh` renders the five adapters into the cache from `colors.sh`.
- Matugen templates live in `matugen/templates/` and are wired to `~/.cache/mlyue-theme/wallpaper/` in `matugen/config.toml`. Keep `reload_apps = false` and `set_wallpaper = false`; the scripts own reloading and wallpaper setting.

## Other
- `wivrn-session` is a standalone VR launcher, not installed by `install.sh`. It starts OscAvMgr/WayVR/VRChat when the WiVRn audio sink appears and only cleans up processes it started.
- `README.md` and `hypr/README.md` are Chinese; keep new user-facing docs Chinese. `hypr/README.md` is a status/design doc that can lag behind code (e.g. autostart now delegates to `desktop-ui.sh`), so trust scripts and config files over it.
